✗ AI開発を殺す「隠匿」

従来の「人間向けの読みやすさ」は、AIにとっては情報の分断です。

Conventional DRY

  • 共通化 (DRY): 1箇所の変更が未知の範囲に波及する。
  • カプセル化: 内部状態が隠され、AIが推論を誤る。
  • 多ファイル分散: コンテキスト窓が細切れの読み込みで枯渇する。
AIは 「隠されたもの」 を推測 (ハルシネーション) します。
規模が大きくなると、この推測のズレが致命的な崩壊を招きます。

A11: Domain-Tagged Values

LLMの「型」は「値」そのものである。

let pos = "world:5,0,2"; // OK
let amount = "usd:9.99"; // OK
let pos = [5, 0, 2]; // NG: 何の座標か不明
  • Context Window 不要: 値だけ見て意味が確定する。
  • 推論ミスを線形に低下: AIが「座標系の取り違え」などの初歩的ミスを構造的に起こせなくなります。
  • Crystallize 整合: Go などの静的型言語への自動翻訳を容易にします。

ボトムアップのTDDはAIを迷わせます。最初に「正解の重力場」を作るのが yume 流です。

Substrate Stable, Runtime Evolves

10年、20年先でも「確実に読める・動く」ことを保証する規律。

  • Zero-Dependency: コアランタイムは標準APIのみで構成。外部ライブラリの死に影響されません。
  • Runtime Pinning: ディレクトリ内に ver001, ver002 ... とランタイムが同居。古いファイルは古いランタイムを選んで永久に動き続けます。
  • Portable: mv folder/ 一発で、履歴・地図・実行環境がすべて移動。

yume-developは、AIの進化に取り残されないための 「不変の基盤 (Substrate)」 を提供します。
