Quick Start

yume-develop は依存ゼロ。Node.js さえあれば今すぐその場で体験できます。

# 1. リポジトリをクローン
git clone https://github.com/AoyamaRito/yume-develop.git
cd yume-develop
# 2. 全てのテストを実行 (190+ cases)
npm test
# 3. ファイル単体で履歴を確認 (Code is History)
node core.module.yume.js history
# 4. 依存グラフの健全性をチェック
node examples/hello.fn.yume.js refs-check .

なぜ yume-develop なのか？

従来の「人間向けの読みやすさ」を優先した設計は、AIにとっては情報の分断を意味します。私たちは、AIが最も効率的に推論し、検証できる構造を追求しています。

01

Code is History

全てのファイルは .yume.js 形式。コードそのものが自身の変更履歴と依存グラフを内包し、外部のGitに頼らずとも自己完結します。

02

Axiom-Driven

15の厳格な「公理」に基づき開発。AIの認知バイアスを排除し、ハルシネーションを構造的に抑制する設計を徹底しています。

03

Top-Down Verification

全体（E2E）から部分（Unit）へ。AIがまずゴールを理解し、その隙間を自律的にテストで埋めていく高度な自動化を実現。

AI-Native 開発の 15 公理

このワークスペースを支配する物理法則。これらに従うことで、AIは本来の知性を100%発揮できます。

A0

認知非対称性

人間向けの「読みやすさ」を捨て、AI向けの「構造的整合性」を追求せよ。

A1

ローカリティ極大化

必要な情報を1つのスコープに集約せよ。共有ヘルパーは物理的な隠匿である。

A3

REAL / SHADOW

JSソースを唯一の真実（REAL）とし、ドキュメントなどは全て派生値（SHADOW）とせよ。

A6

Versions-as-Body

Blockの唯一の実体は、追記専用の履歴配列である。

A11

Domain-Tagged Values

値そのものに型/単位タグ（'world:x,y,z'）を埋め込み、推論ミスを構造的に防げ。

A14

Top-Down Verification

検証は必ず全体（E2E）から部分（Unit）へとトップダウンで進めよ。
