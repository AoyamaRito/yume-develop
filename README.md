# yume-develop

yume-develop is the product-track workspace for AI-Native development. It evolves the concepts proven in `ai-desk v2` into the self-contained `.yume.js` (BLOCKFILE) format.

This repository is intentionally self-contained. It is bootstrapped from `ai-desk v2` and the `yume-files` format work, but it does not require a sibling `yume-files` checkout at runtime.

## Philosophy

Code is history. In yume-develop, every file is a `.yume.js` file that carries its own entire version history, dependency graph, and metadata within itself.

- **All-as-Block**: Functions, constraints, observations, and documentation are all represented as Blocks.
- **Versions-as-Body**: The true state of a Block is its append-only `versions` array.
- **Top-Down E2E-First Verification (Axiom A14)**: Testing starts with End-to-End scenarios to establish the "gravitational field" of context. Unit tests are then autonomously generated by AI to fill coverage gaps identified during E2E execution.

## Contents

- `core.module.yume.js`: Core logic for Block and Graph management.
- `cli.module.yume.js`: The Command Line Interface.
- `runtimes/ver001.handle.yume.js` and `runtimes/ver002.handle.yume.js`: Co-located yume runtimes used by executable `.yume.js` files.
- `runtime.spec.yume.js`: Runtime behavior specification and coverage table.
- `rules.constraint.yume.js`: Constraint Folding engine.
- `eyes.observation.yume.js`: AI-Eyes observation harness.
- `eyes/test/`: AI-Eyes virtual-canvas and observation graph tests.
- `cpu3d.verify.yume.js` (and others): 3Dplus CPU Twin verification logic.
- `3d-prefab/`: A11 domain-tagged coordinate and voxel/prefab flow demo ported from `ai-desk v2`.
- `3dplus/tests/`: CPU 3D Twin tests ported from `ai-desk v2` and pointed at the root `.verify.yume.js` modules.
- `bible.aiDoc.yume.js`: The canonical philosophy and axioms (including A14).
- `onboarding.aiDoc.yume.js`: Rules and guidelines for AI agents working in this repo.
- `examples/hello.fn.yume.js`: Smallest executable yume sample and graph-check entrypoint.
- `e2e.js`: Repository end-to-end test suite covering Block, Graph, CLI, codec, runtime, and virtual-heavy behavior.

## Relationship to ai-desk and yume-files

- `ai-desk`: Research lab and reference implementation. Keep it as the place where broader experiments can live.
- `yume-files`: Format/spec origin. Treat it as lineage, not a runtime dependency.
- `yume-develop`: Mainline product workspace. Runtime, examples, specs, and tests should live in this repository when they are required for normal development.

## Usage

Files in this repository are executable and self-managing.

```bash
# Run the complete local suite
npm test

# Run suites independently
npm run test:e2e
npm run test:prefab
npm run test:3dplus
npm run test:eyes

# List versions of a file
node core.module.yume.js history

# Check the integrity of the reference graph
node examples/hello.fn.yume.js refs-check .

# Move old versions into a sibling plaintext archive
node examples/hello.fn.yume.js trim --keep 5

# Validate canonical yume docs
node runAndReadMe.aiDoc.yume.js validate
node BLOCKFILE.aiDoc.yume.js validate
```

## Completion Standard

- Runtime and repository behavior changes pass `npm test` (`e2e.js` plus `3d-prefab`, `3dplus`, and `eyes` tests).
- Reference graph changes pass `node examples/hello.fn.yume.js refs-check .`.
- Changed `.yume.js` files validate through their co-located runtime.
- Generated `*.archive.yume.js` files stay untracked unless deliberately used as fixtures.
- Public docs explain the current file layout and commands.
